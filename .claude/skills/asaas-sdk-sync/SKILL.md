# asaas-sdk-sync

Most of the SDK is generated from `tools/asaas-openapi.json` plus `tools/endpoint-map.json`. Change inputs, regenerate, verify. Never edit generated files by hand.

## Files

| Path | Role |
|---|---|
| `tools/sync-spec.php` | Fetches docs.asaas.com and rewrites the snapshot and the doc page index |
| `tools/asaas-openapi.json` | Snapshot of the official OpenAPI (generated by sync-spec) |
| `tools/doc-pages.json` | `"METHOD path"` => doc page slug (generated by sync-spec) |
| `tools/endpoint-map.json` | One entry per operation: the canonical SDK surface (hand-maintained) |
| `tools/generator/*.php` | Generator (`generate.php` is the entry point) |

Generated (do not edit): `src/Services/*Service.php`, `src/Http/Requests/**` (including `Common/PaginationRequest.php`), the item models listed in `MapValidator::GENERATED_MODELS` (and their `*List`), `tests/Services/*ServiceTest.php`, `docs/services/*.md`, `docs/README-services.md`, `resources/boost/skills/asaas-sdk-laravel/references/<property>.md`. Each carries a "Generated by ..." header; generated PHP files start with `declare(strict_types=1);`.

Hand-written, never regenerated: `src/AsaasSdk.php` (one property per service, set in the constructor), the runtime (`src/Http/AsaasHttpClient.php`, `RequestBuilder.php`, `ModelConverter.php`, `AsaasRequest`, config, exceptions, provider, helpers), hand-written models (`MapValidator::HAND_WRITTEN_MODELS`), `tests/CoverageTest.php`, `tests/Services/ServiceTestCase.php` and the other tests outside `tests/Services/*ServiceTest.php`, plus README.md, CHANGELOG.md, CONTRIBUTING.md, SECURITY.md, `docs/ai-playbook.md` and `resources/boost/skills/asaas-sdk-laravel/SKILL.md`. Every PHP file, hand-written or generated, starts with `declare(strict_types=1);`.

## 1. Re-sync the spec

```
php tools/sync-spec.php                 # network; writes tools/asaas-openapi.json and tools/doc-pages.json
php tools/sync-spec.php --local=<dir>   # offline: reads <dir>/ref-asaas.txt and <dir>/pages/<slug>.md
```

Other options: `--out=file`, `--pages-out=file`. It exits 1 without writing if any page is missing. Review `git diff tools/asaas-openapi.json tools/doc-pages.json` and note added, removed or renamed operations. The doc page slug is the real page filename (often with a `-1` suffix), matched by verb and path, not by `operationId`.

## 2. Edit tools/endpoint-map.json

Entry keys (all required except the optional ones):

| Key | Rule |
|---|---|
| `method`, `path` | Exactly as in the spec (`/v3/...`). Pair must be unique |
| `category` | Doc category (PT-BR). One category per service |
| `operationId` | From the spec |
| `docSlug` | Must equal `tools/doc-pages.json["METHOD path"]`; the validator fails otherwise |
| `service`, `property` | `XService` class and the `asaas()->property` name. One property per service, unique across services |
| `sdkMethod` | camelCase English verb, unique per service: `list`, `get`, `create`, `update`, `delete`, then specific names (`cancel`, `listPayments`, `createWithCreditCard`) |
| `pathParams` | Names in path order; must equal the spec |
| `hasQuery` | True iff the operation declares query parameters |
| `paginated` | Must equal `Spec::isPaginated` (200 schema has top-level `data` array plus `hasMore` or `totalCount`) |
| `hasBody`, `multipart` | `multipart` must match `multipart/form-data` in the spec (POST only); body and query together are not supported |
| `requestClass` | `Group\\NameRequest`; non-null exactly when `hasBody` or `hasQuery`. Entries sharing a class must have identical rules |
| `responseModel` | A model name, `string` (PDF only) or `void` (204 only) |
| `status`, `notes` | Bookkeeping (`new`, `existing-ok`, `existing-fix`) and free text |
| `rulesFrom`, `allOptional` | Optional: reuse another class's rules (spec with empty body); `allOptional` turns top-level required into nullable |
| `docblockNote`, `docsNote` | Optional: extra docblock line (English) and docs note (PT-BR) |

Pagination: a list method takes `array $params = []` iff the page declares query parameters or the response is paginated. offset min 0 and limit min 1 max 100 come from the official pagination guide.

Naming: code, identifiers, comments and generated tests in English (American); PT-BR only in `docs/` and user-visible messages.

## 3. Sanity constants and models

`MapValidator` pins `EXPECTED_OPERATIONS` (213) and `EXPECTED_SERVICES` (34), and `tests/CoverageTest.php` asserts 213. Update all three together when the operation or service count changes. A new response model is either an existing hand-written model or a new name in `GENERATED_MODELS` (the generator then emits `Name` and `NameList`); an unused generated model is a validation error.

## 4. Regenerate and verify

```
composer generate                                      # same as php tools/generator/generate.php
composer generate:check                                # same as --check --strict
php tools/generator/generate.php                       # write everything
php tools/generator/generate.php --only=PaymentService # subset (the index docs and stale detection are skipped)
php tools/generator/generate.php --out=/scratch/dir    # write to another root
php tools/generator/generate.php --prune               # also delete request classes and references the map no longer uses
php tools/generator/generate.php --check               # no writes; exit 1 on drift or invalid map, stale files are warnings
php tools/generator/generate.php --check --strict      # stale files also count as drift (use this before committing)
```

Finish with `--check --strict` exiting 0. Deleting stale files needs the maintainer's explicit approval: list them first, then `--prune`.

Lint on PHP 8.4 (the minimum supported): `docker run --rm -v "$PWD":/app -w /app php:8.4-cli sh -c 'for f in $(git diff --name-only; git ls-files -o --exclude-standard | grep "\.php$"); do case $f in *.php) php -l $f;; esac; done'`

## 5. Tests (one file at a time, never the whole suite, never parallel)

```
vendor/bin/phpunit --do-not-cache-result tests/CoverageTest.php
vendor/bin/phpunit --do-not-cache-result tests/Services/PaymentServiceTest.php
```

Run `CoverageTest` plus the generated test file of each service you touched, then the hand-written tests the change could affect (`tests/Http/*`, `tests/CustomerServiceTest.php`, `tests/PaymentServiceTest.php`, `tests/ListPaymentsRequestTest.php`). Generated tests use `Http::fake` only, no real calls. Tests must stay compatible with PHPUnit across the CI matrix: no attributes or annotations, `test_*` method names.

## 6. Add an endpoint or service end to end

1. `php tools/sync-spec.php`, confirm the operation is in the snapshot and `tools/doc-pages.json`.
2. Append the entry to `tools/endpoint-map.json` (existing service: reuse `service`, `property`, `category`).
3. New service only: add the `public readonly XService $property;` declaration and the `new XService($client, $config)` assignment in `src/AsaasSdk.php` by hand; bump `EXPECTED_SERVICES`.
4. Bump `EXPECTED_OPERATIONS` and the count in `tests/CoverageTest.php`; add any new model to `GENERATED_MODELS`.
5. `php tools/generator/generate.php`, then step 4 and 5 above.
6. Update hand-written docs that list the surface (README.md, `resources/boost/skills/asaas-sdk-laravel/SKILL.md`) if the service is new.

Removing an operation: delete the entry, update counts, run `--check --strict` to list stale files, get approval, `--prune`.

## 7. Release checklist

1. `composer ci` is green (`format:check`, `analyse`, `generate:check`, `test`); `php -l` clean on PHP 8.4.
2. Set `version` in `composer.json`; follow semver (new operations are minor, removed or changed public signatures are major). Keep it equal to the git tag of the release.
3. Update `CHANGELOG.md` (Keep a Changelog): move the `[Unreleased]` entries into a new `## [X.Y.Z] - YYYY-MM-DD` section, list every breaking change (renamed or removed methods, models, validation changes) under that release, and update the compare links at the bottom. Update README.md if the surface changed.
4. Tag the release `vX.Y.Z` (same version as `composer.json`) on `master` and push the tag; Packagist picks it up.
5. CI matrix in `.github/workflows/tests.yml`: PHP 8.4 to 8.5 times Laravel 12 to 13, prefer-lowest and prefer-stable, plus `composer audit`. Keep `composer.json` constraints (`php ^8.4`, `illuminate/* ^12.0|^13.0`) in step with it; add a matrix entry (and a testbench pair) when a new Laravel or PHP version appears.
6. Never commit a real `ASAAS_API_KEY`; sandbox smoke tests run only GETs and sandbox actions, outside this repo's committed tests.
7. `.gitattributes` export-ignores `/tools`, `/.github`, `/tests` and `/.claude`; `/docs` and `/resources` stay exported (consumers need the skill and the docs).
